# Еженедельный выпуск «Барометра Украины» (инструкция для Claude)

Выпуск готовит облачный агент по [ROUTINE.md](ROUTINE.md); данные собирает GitHub Actions. Публикация — push в main.

Выполнять по вторникам. Язык брифинга — русский. Война оценивается наравне с остальными сферами.

1. **Числа.** `python collect.py` в корне проекта (НБУ, DeepState, Prozorro; Prozorro идёт 5–10 минут, запускать в фоне). Ошибки отметить в `gaps`.
2. **Прошлый брифинг.** Прочитать последний `site/data/briefs/*.json`: статусы сфер и открытый журнал.
3. **Сбор новостей за прошедшую неделю (пн–вс)** веб-поиском, по каждой сфере:
   фронт (ISW, DeepState), энергосистема (Укрэнерго, атаки), ПВО и поставки оружия,
   мобилизация и кадры армии, макроэкономика (Держстат, НБУ, инфляция, ВВП), госфинансы
   (Минфин, МВФ, ЕС), антикоррупция (НАБУ, САП, суды), переговоры и дипломатия, евроинтеграция,
   общество (опросы КМИС и «Рейтинга», беженцы, демография), Россия (экономика, нефть, санкции).
   Каждую цифру подтверждать источником. Если источники расходятся, ставить `unverified: true`.
4. **Журнал.** Для каждой записи со сроком, который уже наступил, или с появившимися новостями
   поставить `status` (done / failed / partial) и короткий `result`. Новые записи добавлять
   с тем же `rec`, если это продолжение старой рекомендации.
5. **Новый брифинг.** Папка `site/data/briefs/<дата вторника>/` с файлами `ru.json`, `uk.json`, `en.json`:
   сначала русская версия по схеме из README, затем полный перевод на украинский и английский.
   Поля `id`, `status`, `score`, `trend`, `level`, `dir`, `due`, `url` во всех трёх файлах совпадают. `number` = прошлый + 1.
   `id` сфер не менять, чтобы работала история статусов. Каждая рекомендация называет реальный
   рычаг президента: указ, СНБО, законопроект, кадры, дипломатия, давление на Кабмин или координация.
   Решения — это предложения. У каждого обязательно поле `effect`: как именно оно улучшило бы ситуацию
   (конкретно, с цифрой, если её можно обосновать).
5б. **Методика.** Для каждой сферы обновить `metrics[].raw` и `value` (кроме `auto`), `conf` по надёжности источника.
   Пороги и веса не трогать; если их всё же нужно поменять — запись в `corrections` с датой и причиной.
   У каждого предложения — `impact` {id сферы: прирост 0.1–1.2}. `regions` — только общеизвестный статус областей.
   Правило безопасности: не публиковать и не сводить вместе данные, которые могли бы помочь противнику
   (конкретные защищаемые объекты, их готовность, позиции). Для защиты энергетики и фортификаций — только агрегаты.
5в. **Проверка фактов.** Отдельным проходом (лучше субагентом) сверить каждую цифру в kpis/metrics/cases с первоисточником
   и поставить `conf`. Расхождения — диапазоном или `unverified: true`.
5г. **Прогнозы.** У каждой записи журнала поле `prob` — вероятность (0–1), что предсказанное случится к сроку `due`.
   Ставь честные вероятности, а не 0 или 1. По наступлении срока: `status` done (сбылось) / failed (не сбылось) / partial и `result`.
   Точность считается автоматически (Brier score).
5д. **Сценарии.** Блок `scenarios`: три сценария на 3 месяца (`base`, `pess`, `opt`) с `prob` (сумма 1), `index` [мин, макс],
   `name`, `text`, `triggers`. Пересматривай вероятности каждую неделю.
5е. **Россия.** Блок `russia`: `lead`, `kpis` (выручка от нефти, экспорт, НПЗ, ставка ЦБ, инфляция, бюджет — с источником и `conf`),
   `note`. `dir` — с точки зрения Украины: рост возможностей РФ = bad.
5ж. **Измеримость.** Если для экспертного подпоказателя (`conf: expert`) появился измеримый аналог — замени его с записью в `corrections`.
5з. **История недели.** Блок `story`: 5–6 шагов {`visual`, `title`, `text`}. `visual` — одно из: `index`, `domain:<id сферы>`,
   `map`, `russia`, `scenarios`. Это короткий связный рассказ о главном за неделю: от общей картины к последствиям и сценариям.
   Цифры в тексте — те же, что в данных выпуска.
5и. **Трекер решений.** Блок `decisions`: решения власти и партнёров за неделю {`date`, `body` (Рада, Президент, Кабмин, НБУ, СНБО, ЕС…),
   `sphere`, `status` (adopted / signed / pending / rejected / vetoed), `title`, `url`, по возможности `rec` — ключ связанного предложения журнала}.
   Важные незавершённые решения (например, застрявшие законопроекты) — со статусом pending.
5к. **Новые автоданные.** Ночная яркость (NASA, `lights.json`) и внимание медиа (GDELT, `media.json`) собираются сами.
   Используй их в анализе: падение яркости в области — признак отключений; всплеск внимания медиа — тема недели.
5а. **Коррупция.** Обновить блок `corruption` (см. прошлый брифинг): `kpis` (CPI, статистика НАБУ/САП),
   `systemic` (оценки потерь бюджета, млрд грн/год, с источником), `cases` (новые и изменившиеся дела: сфера,
   сумма, `uah` числом для пересчёта или 0, стадия, ссылка), `spheres` (риск 1–5 для всех 9 сфер, схемы,
   `without` — что изменилось бы без коррупции, с пересчётом на понятные единицы), `recs` с `effect`.
   Дела описывать только как «по версии следствия», с презумпцией невиновности.
6. **Индекс.** Добавить неделю в `site/data/briefs/index.json` с `period` на трёх языках.
7. **Проверка.** `python build_site.py` — проверяет все выпуски (сферы, веса, effect, одинаковые служебные поля в трёх языках) и пересобирает CSV, RSS и latest.json.
7а. **Соцсети.** `python make_card.py ru` (и uk, en) — карточка и текст поста; `--send`, если заданы токены Telegram.
8. **Публикация.** `git add -A && git commit -m "Выпуск № N: период" && git push` — GitHub Actions выложит сайт и отправит пост в Telegram.
